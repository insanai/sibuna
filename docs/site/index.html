Distributed load balancer and web application firewall

Sibuna routes TCP, UDP and HTTP to healthy servers. We can run one edge or connect several in a mesh, terminate TLS at each edge and apply the firewall to selected HTTP routes.

What is Sibuna? Where we use Sibuna

Open source · LGPL 3.0 · v1.0.0-rc.6

Where we use Sibuna

Public websites

Serve browsers over HTTP/2 or HTTP/3, renew public certificates with Let's Encrypt and inspect requests before forwarding them to HTTP/1.1 replicas.

Internal gRPC services

Issue certificates for internal names with the local CA. Clients trust its root and call the service over TLS. An HTTP/2 backend carries gRPC messages and trailers.

A cluster of edge nodes

Distribute a checked routing configuration across the mesh. Nodes can share bans and learned affinity while each node forwards traffic to its own backend pools.

Where each part stands. RC6 includes the load balancer, firewall and console in one executable.

How to try it

One process on the path

From the socket to the server.

01 / Forward

Connections and datagrams.

TCP streams and UDP mappings go to a pool of servers. A TLS connection can pass through undecrypted, routed by its server name. QUIC can pass through too. The PROXY protocol carries the address of the client.

02 / Terminate and route

HTTPS without a second proxy.

Sibuna terminates TLS and serves HTTP/1.1, HTTP/2, HTTP/3 and WebSocket. It routes each request by host name and path. Certificates come from Let's Encrypt or another ACME authority, and a local authority covers internal names.

03 / Stay up

Change it while it runs.

A checked reload applies new routes to new work. Established TCP streams keep their backend. Linux also supports listener handoff during a binary upgrade.

04 / Scale out

Several nodes, one behaviour.

Nodes of a mesh share the sticky table and the limits of a server, and forward a client to the node that owns it. A PostgreSQL database can publish one configuration to every node and roll it back.

05 / Protect

Ask bots to do the work.

A browser challenge adds a cost to automated access, and a signed session lets an admitted visitor return. Rules allow, challenge or deny. The shield checks requests for SQL injection, XSS, path traversal and command injection.

06 / Extend and observe

See and shape the decisions.

Hooks run at the connection and at the request: compiled in, as WebAssembly with a budget, or in a separate process. Metrics, access logs and a console show servers, flows and the reason for each refusal.

Know the boundary

What it does not do.
Yet, or at all.

We state the limits beside the features. Linux requires kernel 5.10 or later, macOS 12 or later, and Windows 10 or Server 2016 or later. The event-driven workers and the replacement of the executable without lost connections exist on Linux only.

CLI and protocol reference

We tested the cluster on three hosts. Qualification under production traffic remains open. Replacing the executable ends QUIC connections.

The built-in inspector checks the first 8 KiB of supported bodies. WebSocket messages are relayed without inspection. Sibuna does not provide volumetric network mitigation. A challenge adds work. It does not establish that a visitor is human.

The console is opt-in. Its strict performance isolation target has not formally passed. Published measurements identify the code revision and uncertainty.
