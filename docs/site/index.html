Share the cost of access.

Sibuna asks clients to solve a puzzle before granting access. Creating the proof takes more computation than checking it. This helps preserve your app's resources for admitted traffic.

01 / Govern admission

Ask bots to do the work.

Browser challenges add a cost to automated access. Signed sessions let admitted visitors return without a new puzzle on every request. Hardware and difficulty affect the cost.

02 / Protect applications

Keep requests flowing.

Use Sibuna as a reverse proxy or an admission service for your existing ingress. Add native OWASP Core Rule Set inspection when your app needs broader checks.

Know the deployment boundary

Application protection.
Explicit limits.

Terminate public HTTPS at a trusted ingress and keep Sibuna's listener private. Linux requires kernel 5.10 or later; macOS requires 15 or later; Windows requires Windows 10 or Server 2019 or later.

CLI and protocol reference ↗

The built-in inspector checks the first 8 KiB of supported bodies. Native CRS adds request and response inspection within configured limits. WebSocket messages are relayed without inspection. Forward-auth sees the metadata supplied by the ingress.

Your ingress handles public TLS and HTTP/2. Rate limits are local to each node. Sibuna does not provide volumetric network mitigation. A challenge adds work; it does not establish that a visitor is human.

The console is opt-in. Its strict performance isolation target has not formally passed. Published measurements identify the code revision and uncertainty.
